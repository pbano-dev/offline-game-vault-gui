# Release notes

## 0.4.1 — 2026-08-03

### Fixed

- Aligned GUI runner-identifier validation with the core contract.
- Preserved runner IDs may begin with an ASCII letter or digit and may contain
  uppercase letters, digits, `.`, `_`, and `-`, up to 128 characters.
- Added regression coverage for the real preserved runner identifier
  `Proton-9.0-203` and for invalid separators, leading punctuation, and length.

## 0.4.0 — 2026-08-03

### Changed

- Rebuilt the GUI around state-free component composition in core 0.11.4.
- Profiles are treated only as source-layout recipes.
- Acceptance evidence is no longer modeled as profile or runner state.
- Preserved runners are loaded from `list-preserved-runners`.
- UMU backend and Steam Runtime combinations are displayed as diagnostic
  component sets from `list-shared-umu-runtimes`.
- Composition uses only the core `compose` command.
- Play, Verify, and Remove invoke the exact scripts generated by the core.
- Bottles uses the managed path discovered by the core.
- Direct-Wine and UMU destinations are checked against the collection root and
  must not already exist.
- Added a headless synthetic-core integration suite.
- Added repository contract, privacy, syntax, and packaging validation.

### Removed

- Profile maturity and acceptance-state fields.
- Experimental-variant terminology and selection services.
- GUI-side runner overrides and system-runner fallback.
- GUI-side UMU backend reconstruction.
- Any assumption that a successful materialization transfers functional
  acceptance.
