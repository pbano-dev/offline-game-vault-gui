# Architecture

## Purpose

OfflineGameVault GUI is a presentation and orchestration layer. The vault and the `offline-game-vault` core remain authoritative.

## Selection identity

A derived variant is identified by at least:

```text
capsule_id
profile_id
backend
runner
save_set
```

Changing any of these values creates a different variant. Functional acceptance does not transfer automatically.

## Backends

### Bottles

The GUI creates a temporary, verified materialization, converts the neutral game object into a derived Bottles source, restores the selected state, and deploys it through the preserved Bottles backend. The heavy final copy remains in the Bottles-managed location.

### Direct-Wine

The GUI derives a temporary playable contract. A neutral object is materialized once under `source/`; the runner is materialized separately. The game is exposed inside the prefix through a relative link generated by prefix operations.

### Windows export

The GUI produces a candidate Windows package. It does not execute the game and does not mark the profile as verified.

### Base-only

The GUI extracts and verifies objects without creating a playable launcher.

## Save sets

Save sets may contain one or more files or directories. All payload items are verified and applied as one logical selection. Partial state publication is rejected.

## Imported candidates

Imported capsules may leave the runner unbound. The GUI then offers shared runner objects from the vault at materialization time.

## Trust boundary

The GUI must not redefine capsule facts, silently download components, or mutate immutable objects. Temporary overlays are receipts-bound derived inputs.
